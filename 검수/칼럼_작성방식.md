# 홈페이지 칼럼 작성 방식

홈페이지 칼럼은 AI(챗GPT·구글·네이버 AI 브리핑)가 인용하는 '공식 답'입니다. 블로그(경험·사례)와 역할을 나눕니다.

## 기본 원칙
- 환자 질문 하나 = 페이지 하나. 위치는 질환 폴더 아래 (예: `/dizziness/recurrent-bppv/`).
- 한 질문에 답하는 페이지는 하나만 둡니다(키워드 잠식 방지, 2026-10-24 원장님 결정). 쓰기 전에 `site.config.json`의 같은 질환 칼럼들(h1·소제목·FAQ)과 비교해, 같은 질문에 답하게 되면 쓰지 않고 주제를 '보류(기존 칼럼과 중복)'로 바꿉니다. 일부만 겹치면 이 칼럼의 초점을 좁히고, 겹치는 부분은 한두 문장 + 기존 칼럼 링크로 넘깁니다. 같은 질환 칼럼끼리는 본문에서 서로 링크합니다.
- 블로그 글의 문장을 옮기지 않습니다(네이버 유사문서). 블로그에서 질문만 뽑아 새로 쓰고, 끝에 블로그 원문을 '자세한 경과 보기'로 연결합니다.
- 사실은 원장님 블로그 원문, 원장님이 준 자료, `D:\guwol-youtube\배경자료\`(01 기본정보, 02 원장님 관점, 03 표현 규칙)에 있는 것만 씁니다.

## 본능 분석 — 칼럼마다 두 가지를 보여 줍니다
- **실력**: 이 질문에 대한 원장님의 기전 설명(배경자료 02 관점), 검사(혈액·자율신경·뇌파), 진료 연차(2014년부터), 해당 질환 사례.
- **진정성**: 환자가 실제로 하는 말로 시작하는 공감, 다른 진료가 먼저인 경우를 먼저 알려 주기, 치료 과정·기간·비용·환불 기준을 숨기지 않기.

## 반박 제거 — 칼럼마다 이 질문의 반박을 먼저 꺼내 답합니다
각 칼럼은 `검수/본능_반박_리스트.md`의 해당 질환 반박 중 **이 주제와 관련된 2~3개**를 소제목이나 FAQ로 직접 다룹니다. 공통 5가지는 빠짐없이 어딘가에서 답이 보여야 합니다(본문, FAQ, 또는 링크).
1. 잘 고치나 (효과·기간) → 기전 + 사례 + 15일 경과 확인, 보통 1~3개월
2. 부담·부작용 없나 → 처방 전 혈액검사(간·신장), 복용 약 상호작용 확인, GMP 약재
3. 과잉진료 아닌가 → 다른 진료가 먼저인 경우 안내, 중단 시 15일 단위 차감 환불
4. 비싸지 않나 → `/npay/` 비급여 안내 링크 (할인율은 쓰지 않음)
5. 원장 믿을 만한가 → 대표원장 직접 상담·경과 확인, 약력

## 구성 (순서) — 블로그처럼 증상 → 공감 → 가치입증 → 내용 (2026-11-24 원장님)
원장님: "증상 나열부터 해야지. 공감을 먼저하고 가치입증을 하고 그다음에 내용을 전개해. 블로그쓰는것처럼", "이상한마케팅 병원아카데미 내용참고해봐". 아카데미 「병원 블로그 심화 2탄」 도입부 공식(고객 목소리 → 공감 → 가치입증 → 해결책 미리보기)과 같습니다. 예: `/peripheral-neuropathy/night-burning-pain/`, `/tinnitus/anxiety-panic/`.
1. 제목: 환자가 AI에게 묻는 문장 그대로
2. `lead`(맨 위 요약): 증상 질문 한 문장("밤마다 얼음팩으로 발을 감싸야 겨우 잠드시나요?") → 공감과 결론 한 문장 → "13년째 ○○을 진료해 온 대표원장이 …을 차례로 설명합니다". 결론은 `description`에도 둡니다.
3. **증상 나열**: "혹시 이런 ○○을 겪고 계신가요?" 체크 목록(`ul.checklist`) 5~7줄 + "두 가지 이상 해당된다면 끝까지 읽어 보세요". 증상은 블로그 원문 표현에서.
4. **공감**: 환자 말 인용 2~3개(원문 그대로) + 공감 단락 1~2개(이미 해 본 치료, 들어 온 말, 그 증상으로 무너진 일상).
5. **가치입증**: 소제목 "13년째 ○○을 진료하며 지켜본 답". 첫 줄에 굵게 결론 1~2문장(AI 인용용) → 진료 연차·이력 → 원장님이 만든 약력 카드나 실제 사진 1장 → 대표 사례 한 줄(자세한 경과는 아래 사례로) → 해결책 미리보기("…을 차례로 말씀드리겠습니다").
6. 질문형 소제목 3~5개, 각 소제목 첫 문장에 바로 답 (반박 제거를 여기서), 원장 관점 설명 (실력)
7. 진료 과정(이렇게 봅니다) + `/npay/` 링크
8. 사례 요약 + "경과는 개인에 따라 다를 수 있습니다" + 블로그 원문 링크
9. 다른 진료가 먼저인 경우
10. FAQ 3~4개 (`site.config.json`의 `faq`, FAQPage 구조화 데이터로 자동 생성)
11. 상담 안내 (빌드가 자동으로 붙임, 비용 안내 링크 포함)
- 이미 공개한 칼럼에 같은 순서를 적용할지는 원장님이 따로 정합니다.

## 표현
- '전문', 다른 병원·치료 깎아내리기, 할인·무료·이벤트 문구는 쓰지 않습니다.
- '한방'(한방 진료·한방 치료·한방치료)이라는 말은 쓰지 않습니다(2026-11-13 원장님). '진료', '한의 치료', '한의원에서 치료'로 씁니다. 학회·기관 이름 같은 고유명사는 그대로 둡니다.
- 길이 1,500~3,000자. `python build.py`의 표현 검사와 `D:\guwol-site-audit` 점검을 통과해야 합니다.

## 그림 (2026-10-24 원장님 결정: 블로그 설명 그림 사용)
- 근거로 쓴 블로그 글 PDF에 원장님이 만든 **설명 그림(모식도·그래프·흐름도)**이 있으면 칼럼에 1~2개 넣습니다. 같은 이미지를 써도 검색 불이익이 확인되지 않아 쓰기로 했습니다.
- 넣지 않는 것: 환자 얼굴이 보이는 사진, 자필 후기, 처방 구성(약재) 그림, 인물·상황 연출 이미지(AI로 만든 것 포함), 차트 화면.
- 그림 내용은 본문 글자로도 씁니다(그림 속 글자는 검색엔진·AI가 읽지 못함). 그림 아래 `figcaption`에 한 줄 설명, `alt`에 그림 내용을 문장으로.
- 방법: PDF에서 `pdfimages -all`로 뽑아 webp로 바꿔 `images/columns/<질환>-<내용>.webp`에 두고, 본문에 `<figure class="figure"><img ... width height loading="lazy"><figcaption>…</figcaption></figure>`로 넣습니다. 예: `/tinnitus/worse-at-night/`.
- **원장님이 영상용으로 다시 그린 그림이 있으면 블로그 그림보다 먼저 씁니다** (2026-11-21 원장님: 메니에르 모식도를 세모 단면에서 달팽이 모양으로 바꿨는데 칼럼에 옛 블로그 세모 그림이 들어감). 같은 내용의 그림을 고르기 전에 guwol-youtube 저장소의 `motion/*.html`(설명 모션그래픽 원본)과 `회차/*/편집작업/broll/`을 먼저 찾고, 회차 기록(`쇼츠_업로드.md` 등)에 '그림을 바꿨다'는 원장님 말씀이 있는지 확인합니다. 예: 메니에르 림프액 → `motion/meniere06.html` lymph(`/images/columns/dizziness-meniere-lymph-steps.webp`).
- **과정을 설명하는 그림은 한 장면만 넣지 않고 변화 단계를 모두 보여 줍니다** (같은 날 원장님: "모식도를 하나만 보여주면 그 과정이 뭔지 모르잖아. 변화과정을 다 보여줘야지"). 움직이는 그림이나 단계별 그림이면 단계마다 한 장씩 뽑아 번호(①②③…)를 붙여 한 그림으로 묶고(휴대폰에서 읽히게 2열), `figcaption`에도 단계를 순서대로 적습니다. 블로그 PDF에서 뽑은 그림이 움직이는 그림의 첫 장면(① 표시만 있는 것)이면 그대로 쓰지 않습니다.
- 그림·사진은 연달아 붙여 넣지 않습니다. 사이에 본문 단락을 두고 서로 다른 소제목 아래에 나눠 둡니다 (2026-10-28 원장님 요청).
- 진료실 사진은 칼럼마다 돌려 씁니다. 상담 사진(`clinic-consultation`, 대표원장이 책상에서 받아 적고 환자분은 뒷모습만 보이는 사진)은 이미 여러 칼럼에 들어가 있어 새 칼럼에는 넣지 않습니다. 사진을 고를 때는 `src/pages`에서 쓴 횟수를 세어 적게 쓴 사진부터 고릅니다 (2026-11-12 원장님: "이 사진 말고 다른 사진도 좀 쓰라고 했잖아").
- 실제 사진(상담·검사실·탕전실·입구) 배치와 SVG로 새로 그리는 기준은 아직 논의 중입니다. 정해지기 전에는 위 설명 그림만 넣습니다.
